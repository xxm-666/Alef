# Alef iOS UI 第二版：需求对照与完善说明



依据：[ios_ui_functional_spec.md](https://chatgpt.com/library?file\_id=libfile\_fe2a617b77f88191b4c9d451f34dc8f6\&account\_id=personal)。文档共 7 个功能模块。对照对象是上一轮生成的「今日学习、字母总览、字母详情、单词词库、单词详情、复习练习」6 个设计页面。Figma 调用额度限制使本轮无法重新读取或修改原文件；以下不假定文件在上一轮后没有外部改动。



## 结论



首版建立了配色、基础排版和学习卡片的视觉方向，但尚不足以作为这份功能清单的完整开发依据。主要缺口是功能入口、详情信息层级、练习的完整流程、个性化设置与状态反馈，而不是缺少装饰。



第二版保留暖白、深海蓝和统一圆角，调整信息架构为「字母、词库、练习、规则、我的」5 个主模块。原「今日学习」内容拆成各模块顶部的继续学习和到期提醒，个人统计集中在「我的」。这样补充大量功能时，不必无限增加首页卡片或底部标签。



本轮新增的是可探索的界面原型及本说明，没有更新 Figma 原稿。原型为设计演示：音频、手写体字形、真实间隔重复调度、完整学习数据、本地持久化及原生 Widget 没有实现；示例数据与统计不代表用户真实记录。

## 三、关键界面应该怎样完善



### 1. 字母总览：保持入门清爽，同时容纳 13 项信息



默认只开启印刷体、英文名、掌握度，并在适用字母显示词尾形式。入门用户不需要同时面对古典读音、字源和多套音译。



显示项包含：印刷体、手写体、词尾形、达盖什字形、希伯来语名称、英文名称、中文名称、现代读音、古典读音、音译、Gematria、掌握度、分类标签。完整开关放在同一个面板中；调整时示例卡应实时预览，完成后返回字母表。选项很多时卡片自然增高，不能缩小到无法辨认元音点的字号。



真实设计稿还需画出默认、精学、全部关闭的最小合法状态和大字模式。若全部关键内容关闭，应保留至少一种字形，或明确限制，避免产生没有可辨识内容的卡片。原型尚未实现这一开关约束。



总览中的播放与掌握度需要独立可点区域，不能依赖长按才可发现。建议点击卡片进入详情；「快速操作」展示发音与三态掌握度按钮，避免在同一卡片上让一个单击同时承担两种动作。本轮原型以详情操作为主，Figma 后续需补画快速操作状态。



### 2. 字母详情：把基础认读与精学信息分开



首屏顺序：前后字母 → 大字形 → 现代发音与发音按钮 → 掌握度。下面依次为印刷/手写对照、适用字母的词尾与达盖什、代表例词、现代/古典差异、Gematria/本义/字源/书写说明、易混字母。



不要把「古典读音」仅作为现代发音的一行附注；两者要有明确标签。词尾扩展数值也要注明采用的计数法，不应与标准 Gematria 无区分地并列。



手写体必须使用真实希伯来手写字形资源。把印刷体倾斜，不能当作手写体。原型明确保留了待补的手写字形区域，没有伪造手写字形。



### 3. 词库与详情：把搜索、筛选与复习连起来



搜索提示无需列完全部支持字段，可用「希伯来语、中文、音译、词根…」。筛选面板承接范围、11 主题、首字母及排序；搜索结果处显示当前范围和结果数量。应能清除无结果筛选。



详情首屏放词形、中文、音译、IPA、播放与收藏。掌握度独立为三态操作，下方明确下一次复习。更深的信息按「例句与朗读 → 词性/语法/用法 → 词根 → 字母拆解 → 同根词 → 词形变化」组织。没有变形的词不显示空列表；每个真实变形有独立音频入口。原型仅使用小量例词演示版式，关联词数据和完整变形仍需正式数据源。



### 4. 练习：补齐题目前后，而不只画一道题



必须区分自由练习与到期复习。自由练习允许换题；到期复习显示队列进度，正确与错误都会在提交后明确反馈，再进入下一题，最终汇总结果。



需要画出的状态：未选择、已选择未提交、正确、错误及正确答案、解释、不可播放、空队列、完成结果。错误反馈不能只靠红色；应同时有文字和符号。



拼写题提供独立 RTL 输入区，屏内键盘含 22 字母与 5 词尾形，另有删除和系统键盘入口。是否忽略 Niqqud、允许何种拼写差异、答案规范化规则需由内容与业务逻辑明确。



学习中的下一次复习是 1 天后，已掌握的递增间隔为 3 / 7 / 14 / 30 天，来自需求清单。后续需要明确「按何种复习历史递增」「答错如何重置」；不能只靠用户反复点击已掌握按钮推进复习阶梯。原型显示的是安排样式，不运行正式 SRS 算法。



### 5. 设置：全局能力集中，但在学习现场留入口



六种外观：跟随系统、白色、羊皮纸、玫瑰、紫罗兰、深色。所有主题共享字号、间距、控件和层级，只替换颜色与材料。排列方向影响字母序列，不能顺便把整个中文界面镜像。



发音设置放全局语速 0.50×–1.50×、试听、离线录音数量和反馈音效。短语固定慢速仍独立标注为 0.68×。录音优先、系统 he-IL 回退和音译回退属于不同音源，遇到异常时需要可理解的提示，不能让用户误以为所有语音都是母语真人录音。



备份页面依次是导出、复制、文件恢复、文本恢复。恢复流程必须先检查格式，再展示真实将变更的数据项及数量，然后确认。成功后可撤销最近一次导入。原型支持示例掌握度/收藏/队列的校验、预览、确认与撤销；统计和偏好恢复、真正的文件导出/剪贴板动作尚未实现。



## 四、统一视觉规范



| 项目 | 第二版规范 |

|---|---|

| 主视觉 | 暖白背景、深海蓝强调；内容区实底，导航与临时操作层使用克制的半透明材料 |

| 文字 | 中文说明、希伯来字形、音译和 IPA 分别排版；希伯来内容独立 RTL；混排使用方向隔离 |

| 字形 | 辅音和 Niqqud 作为完整字素显示；不拆组合标记；留足上下行高 |

| 组件 | 全局复用主按钮、次按钮、图标按钮、分段、筛选、词条、状态标签和掌握度选择 |

| 操作位置 | 前后页、收藏、播放、提交位置在同类页面保持一致；图标操作有可访问名称 |

| 点击区域 | 主要触控目标约 44 pt 或更大；小字号不用于关键操作 |

| 状态反馈 | 正确、错误、收藏、掌握度同时有文字与图标；不只依赖颜色 |

| iOS 适配 | 以系统安全区、Dynamic Type、VoiceOver、减少透明度/动态效果为实现约束 |

| 深浅主题 | 不能只反转背景；文字、分隔、选中、错误、成功与浮层分别检查对比度 |



交互原型使用网页模拟移动界面。原生玻璃折射、滚动边缘效果、系统菜单/键盘和真实触感，必须在 SwiftUI/UIKit 中验证，不能把网页或 Figma 的静态半透明效果等同于系统渲染。

## 六、验收标准与本轮验证范围



完成设计稿的标准应是「每条需求都有入口、操作状态和返回路径」，而不是「所有页面都有一张截图」。每条要求最终关联 Figma Frame / Component / Prototype Flow；未实现功能不写成已完成。



本轮已完成需求全文对照、页面与面板原型、脚本语法检查及模拟 DOM 交互检查。模拟检查覆盖：22 字母、13 显示开关、搜索无结果与清除、词详情与字母跳转、到期复习提交/反馈/结果/空队列、拼写键盘、六主题、无效备份/预览/确认/撤销，以及全部页面路由渲染。



尚未进行浏览器像素级复核、VoiceOver 与 Dynamic Type 真机测试。浏览器不允许打开当前本地文件地址；没有绕过该限制。Figma 原文件也未修改。正式手写字形、音频与课程内容需要独立的语言准确性审核。
